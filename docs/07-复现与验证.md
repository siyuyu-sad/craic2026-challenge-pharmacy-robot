# 07 复现与验证

## 环境

| 项 | 值 |
| --- | --- |
| 系统 | Ubuntu 18.04（树莓派 Ubuntu MATE / 虚拟机同源） |
| ROS | Melodic |
| Python | 2.7（代码里 `isinstance(..., unicode)` 是 py2 专有） |
| OpenCV | 3.2（`cv2.findContours` 返回 3 个值） |
| 识别 | `pyzbar` + `libzbar0`；`pytesseract` + `tesseract-ocr` + `tesseract-ocr-chi-sim` |
| 导航 | `move_base`（`teb_local_planner` 或默认 DWA）、`amcl`、`map_server` |
| 相机 | Orbbec Astra（厂商平台配置，`roslaunch astra_camera astra.launch`）；识别节点另走 `web_video_server` 的 MJPEG 流 |

安装（除 ROS 自带包外）：

```bash
sudo apt install libzbar0 tesseract-ocr tesseract-ocr-chi-sim
pip2 install pyzbar pytesseract    # 或 rosdep 里已有的版本
sudo apt install ros-melodic-web-video-server
```

## 部署

代码原路径是 `~/robot_ws/src/pharmacy_pkg/scripts/`，仓库里的 `src/pharmacy_pkg/scripts/` 与之对应：

```bash
cp -r src/pharmacy_pkg ~/robot_ws/src/
cd ~/robot_ws && catkin_make
chmod +x ~/robot_ws/src/pharmacy_pkg/scripts/*.py
```

三个节点的启动顺序：

```bash
# 1. 底盘/导航/相机（沿用厂商 launch）
roslaunch base_control base_control.launch
roslaunch astra_camera astra.launch
roslaunch robot_navigation robot_navigation.launch     # 载入赛前建好的地图

# 2. 相机 MJPEG 转流（识别节点靠它取图）
rosrun web_video_server web_video_server                # 默认 8080 端口

# 3. 识别节点
rosrun pharmacy_pkg F1_detect_code.py
rosrun pharmacy_pkg OCR_CAM.py _headless:=true

# 4. 任务节点（最后启动，它会等 move_base）
rosrun pharmacy_pkg F1_yaofang.py
```

## 验证

### 已在本仓库做过的静态验证

| 检查 | 方法 | 结果 |
| --- | --- | --- |
| 语法 | `python -m py_compile` × 3 | 全部通过（py3 解释器只做语法检查；运行时依赖 ROS/py2，不能真正导入） |
| 节点间协议一致 | 对照 `F1_detect_code.py` 的发布与 `F1_yaofang.py` 的校验 | 一致，见下表 |
| 基线与改动量 | `difflib` 对比厂商脚本 | `F1_yaofang.py` 0.07（重写）、`F1_detect_code.py` 0.82（改造）、`OCR_CAM.py` 0.08（重写） |

`/cam_return` 的 6 字段静态对照：

| 位置 | 通道 | 字段 | 行号 |
| --- | --- | --- | --- |
| 发布 | `/cam_return` | `[goC, goA, goB, 样本数, 板位, Error_count]` | `F1_detect_code.py:340-391` |
| 订阅 | `/cam_return` | `len(msg.data) >= 6` 才收 | `F1_yaofang.py:461-465` |
| 校验 | — | `result[3] ∈ {1,2,3}`、`result[4] ∈ {0..3}`、`result[0:3] ⊆ {0,1}` | `F1_yaofang.py:292-297` |
| 使用 | — | `windows_go=[0..2]`、`sample_count=result[3]`、`lab_window=result[4]` | `F1_yaofang.py:300-305` |

### 上车验证步骤（按顺序，每步都能单独失败）

1. **相机流**：`rosrun web_video_server web_video_server` 后浏览器打开 `http://<车IP>:8080/stream?topic=/camera/rgb/image_raw`，确认有画面
2. **二值化效果**：`rosrun pharmacy_pkg OCR_CAM.py`，看 `OCR - ROI Binary` 窗口，字形必须完整、无大面积黑块；不合格要调 `~roi` 与阈值参数
3. **二维码解码**：把 `aera1..4.jpg` 拿出来直接 `zbarimg` 解一遍，确认四块各自能解出串；解不出说明透视归一化的四点匹配错了
4. **服务**：`rosservice call /request_recognition`，返回里应带 `message="[...]"`；返回 `No result yet` 说明识别还没成功过
5. **上报**：在裁判端那台机器上 `nc -l 8888` 或用 `python -c "import socket..."` 起个监听，确认每秒一行 JSON 且字段齐全
6. **整轮**：从起点跑一轮，掐表；单轮超 240 s 就要回看是哪一段顶到了 30 s 上限

### 离线可做的单元测试方向（本次未做）

三个脚本都是顶层过程式代码（`F1_detect_code.py` 的循环直接写在模块级），**不可 import、无法单独测函数**。要加测试，第一步是把纯逻辑抽成函数：

| 抽出来的函数 | 输入 | 应覆盖的用例 |
| --- | --- | --- |
| `parse_result(text)` (OCR) | 识别串 | 空串、只有「空闲」、只有「忙碌」、两者都有、`等待 3 秒`（越界）、`等待 8 秒`、无数字 |
| `vote(all_data)` (QR) | 四区域解码串 | 全空、单区域、`ABC`、非法串 `ABD`、两区域同长 |
| `is_valid(result)` (任务) | 6 字段数组 | 长度 5、`result[3]=4`、`result[4]=5`、`result[0:3]=[1,2,0]` |

这三个函数纯 Python、无 ROS 依赖，抽出来就能在 CI 里跑（pytest），也是把「可验证的产出」从口头变成测试用例的最短路径。

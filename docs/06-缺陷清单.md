# 06 缺陷清单

比赛版代码是按「现场能跑」的标准收敛的，以下问题都在读代码时确认过，**没有在比赛版里改**（改动需要上车回归，赛期不具备条件）。按严重程度排序，附最小修法。

## P0：视频流断开时节点崩溃，且不留日志

`F1_detect_code.py:104-129`

```python
hx, frame = cap.read()                 # :107
height, width = frame.shape[:2]        # :110  ← 在 hx 判定之前就用了 frame
...
if hx is False:                        # :125  ← 太晚了
    print('read video error')          # :127
    exit(0)                            # :129
```

`cap.read()` 失败时返回 `(False, None)`，此时 `:110` 的 `frame.shape` 直接抛 `AttributeError: 'NoneType' object has no attribute 'shape'`，进程带着 traceback 退出。

现象：**车跑到一半，识别节点整个消失**，`/cam_return` 不再更新，任务侧 3 s 超时后回退默认处方，接下来整轮按「ABC 三窗口」跑——流程没断，但识别分全丢。因为 traceback 打在 stdout、比赛时没人盯终端，这个问题很难定位。

**最小修法**（把判定提到最前，并把 `exit` 改成 continue）：

```python
while not rospy.is_shutdown():
    hx, frame = cap.read()
    if not hx or frame is None:
        rospy.logwarn_throttle(2.0, "【识别】视频流读取失败，等待重连")
        time.sleep(0.2)
        continue
    height, width = frame.shape[:2]
    ...
```

顺带把 `exit(0)` 删掉：单帧读失败是网络抖动，不是不可恢复错误，`exit` 让「抖动」升级成「进程死亡」。

## P1：识别等待固定 4 s，结果到了也不提前退出

`F1_yaofang.py:277-289`，详见 [`05-限时与跑位.md`](05-限时与跑位.md)。

```python
while waited < max_wait and not rospy.is_shutdown():
    ...收集...
    # 缺 break
```

**修法**：把合法性校验抽成函数，收集循环里判到合法结果立即 `break`，`max_wait` 从 3.0 降到 1.5。

```python
def _valid(self, result):
    return (len(result) >= 6 and result[3] in (1,2,3) and result[4] in (0,1,2,3)
            and all(v in (0,1) for v in result[0:3]))

while waited < max_wait and not rospy.is_shutdown():
    rospy.sleep(0.5); waited += 0.5
    if self.current_result and self._valid(self.current_result):
        self.received_results.append(list(self.current_result))
        break
```

## P1：`visit_all_labs` 分支不可达

`F1_yaofang.py:380-395` 的「遍历全部化验区」分支要求 `self.visit_all_labs == True`，但全文只有 `= False` 的赋值（`:213、:323、:331、:437`），**没有任何一处置 True**。

影响：45 行代码从未执行，是纯负担；也说明「全化验区巡查」这个策略在比赛版里被放弃了（时间不够）。

**修法**：删掉分支，或补上置 True 的条件（例如 `lab_window` 越界时兜底全跑）。

## P2：OCR 的「成功率」口径是「有输出率」

`OCR_CAM.py:108-112`

```python
if text:
    is_busy, wait_time = parse_result(text)
    STATS["success"] += 1        # 只要 Tesseract 吐了字就算成功
```

退出时打印 `成功率: %d/%d`（`:140`），但分子包含「认出错字」「忙/闲判反」的帧。这个数字**不能当准确率用**（`RESUME.md` 已标注）。

**修法**：把成功定义成「解析结果落在物理区间」（`5 ≤ n ≤ 10`）或人工标注集上的正确率。

## P2：`confidence` 是死字段

`OCR_CAM.py:48`：`confidence = 0.8 if text else 0.0` —— 常量占位，从未参与决策，也没有对外发布。

**修法**：删掉返回值里的 `confidence`，或改用 `pytesseract.image_to_data` 的真实置信度并用阈值过滤。

## P2：`/board2_result` 无订阅者

`OCR_CAM.py:76` 发布 `/board2_result`，本仓库三个节点里没有任何订阅方。板2 状态识别是独立跑通的能力，但未接入任务流。

价值判断：把「窗口忙碌 + 等待秒数」接入调度（例如忙碌窗口延后访问）是明显的策略增益，但需要在 4 min 预算里留出重试时间，赛期未做。

## P3：`img_len` 变量名与实际语义不符

`F1_detect_code.py:309-321`

```python
img_len = [0,0,0,0]
if len(img0_data) < 4: img_len[0] = len(img0_data)   # 只记 <4 的长度
max_img = max(img_len)          # 实际含义：最长解码串的字符数（0..3）
windows_count = img_len.index(max_img)   # 实际含义：是哪个板位
```

`windows_count` 这个名字尤其误导——它是**板位序号**（0..3，后面被任务侧当 `lab_window` 用），不是「窗口数量」。

**修法**：重命名为 `decoded_len` / `area_idx`，并把 `max_img == 0`（四区域全空）从「静默不发布」改成发布一个明确的 `invalid` 标志，让任务侧不用靠超时区分「没识别」和「识别失败」。

## P3：识别参数写死在模块顶层

`F1_detect_code.py:33-38`：`approxPolyDP_epslion`、`wh_rate`、`min_area`、`max_area`、`min_center_distance` 都是模块常量，换场地/换板子要改代码。而 `OCR_CAM.py` 已经把 ROI/相机索引走 ROS 参数了——两个节点的配置风格不统一。

**修法**：抽成 `rospy.get_param('~qr/wh_rate', 0.4)` 这类带默认值的参数，配 launch 文件。

## P3：`cv2.imshow` 依赖图形界面

`F1_detect_code.py:402` 有 `cv2.waitKey(1)`（循环节流），调试用的 `imshow` 已注释但依赖仍在；`OCR_CAM.py` 的 `~headless` 默认 `False`，在无 X 的环境会抛 `cv2.error`。车上跑要么保证 DISPLAY，要么统一 `headless=True`。

## P3：Python 2 专有写法

`F1_yaofang.py:118`

```python
if isinstance(json_str, unicode):     # Python 2 专有
    json_str = json_str.encode("utf-8")
```

ROS Melodic 默认 Python 2.7 所以现场没暴露，但迁 Noetic/py3 会 `NameError`。py3 对应写法：

```python
if isinstance(json_str, str):
    json_str = json_str.encode("utf-8")
```

（`sendall` 需要 bytes，py3 下 `json.dumps` 返回 str。）

## 汇总

| 级别 | 数量 | 是否影响比赛成绩 |
| --- | --- | --- |
| P0 | 1 | 是（识别节点中途死亡） |
| P1 | 2 | 是（时间浪费 / 死代码） |
| P2 | 3 | 部分是（指标口径、能力未接入） |
| P3 | 4 | 否（可维护性） |

面试时挑 P0 讲：现象 → 定位 → 根因（判定顺序）→ 修法（前移判定 + 去 `exit`）→ 复现方法（拔网线/停流 2 s）。这个故事比「我负责识别模块」有信息量得多。

# 04 识别板2 文字识别

`OCR_CAM.py`（143 行）读的是第二块板——化验窗口的状态牌，例如：

```
化验区 忙碌中
等待 8 秒
```

需要输出两个值：**忙/闲**、**等待秒数**。它是完整的独立能力，但**没有接入任务决策**——车侧送检按处方板位直送，这一点是规则要求与实现之间的差口（见 [`05-限时与跑位.md`](05-限时与跑位.md#规则里的化验区空闲识别在实现里是什么位置)）。

## 与厂商示例的差别

厂商基线 `OCR_CAM_0506.py`（78 行）是「全屏二值化 + 字符白名单投票」：把整帧灰度、固定阈值 127，用 `chi_sim_baidu` 训练数据识别，再从结果里找 `化/验/区/血/常/规/...` 这些单字，最后靠 `if "血" in result: if "空" in result: output = ...` 拼句子。

问题：

- 全屏二值化对反光、半幅阴影几乎不可用
- 字符投票只看「出现了哪些字」，两行文字顺序信息丢失
- `if` 并列写法：`if "空" in result` 与 `if "忙" in result` 同级顺序执行，同一帧两个条件都成立时 `output` 被后写的覆盖（固定偏向「忙碌」），属于静默错误
- `while True` 无 `sleep`，空转吃满一个核

新版换成了「ROS 节点 + ROI + 自适应阈值 + 排版感知的 Tesseract + 语义解析」，相似度 0.08（`difflib`），基本是重写。

## 处理链

### 1. 固定 ROI（`:17-19`）

```python
CAMERA_WIDTH, CAMERA_HEIGHT = 1280, 720
ROI_REGION = (100, 150, 600, 424)   # x, y, w, h
```

板子在画面中的位置赛前标定一次即固定。**不追求自动定位**：比赛只有一块板、一种停车位，自动检测 ROI 的收益为负（多一层失败模式、多几十毫秒）。

参数通过 ROS 参数可覆盖（`:79-82`）：`~camera_index`、`~roi`、`~headless`，方便换车位时只改 launch 不改代码。

### 2. 预处理（`:27-40`）

```python
gray = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY)
denoised = cv2.GaussianBlur(gray, (3, 3), 0)
binary = cv2.adaptiveThreshold(denoised, 255,
                               cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
                               cv2.THRESH_BINARY, 11, 2)
```

- 白底黑字，自适应阈值按局部邻域算门限，抗反光/阴影；`blockSize=11` 足够小以贴合字形又不会引入方框伪影，`C=2` 是典型的轻微偏移
- 3×3 高斯放在阈值化**之前**：先去噪再二值化，避免噪点先被固化成黑点
- ROI 边界做了 clamp（`:29-31`），防止参数传越界导致切片为空

### 3. 版面切分（`:43-49`）

```python
config = '--oem 3 --psm 6 -l chi_sim'
raw = pytesseract.image_to_string(img_binary, config=config)
text = re.sub(r'[\s\n\t\r]', '', raw)
```

- `--psm 6`（假设为单个统一文本块）最适合「两行居中排版」的牌子：不会被当成表格或稀疏文本切碎
- `--oem 3` 用默认的 LSTM+legacy 混合引擎，中文小字号下比单 legacy 稳
- 去掉所有空白后做关键词匹配，避免换行/空格干扰

### 4. 语义解析（`:52-71`）

```python
FREE_KEYWORDS = ['空闲', '通过']
BUSY_KEYWORDS = ['忙碌', '等待']
...
if is_free and not is_busy:
    return False, 0
if is_busy:
    m = re.search(r'(\d+)\s*秒', text)     # 优先带单位
    ...
    if 5 <= n <= 10: return True, n         # 物理区间约束
    return True, 8                          # 缺省/越界 → 8
return False, 0
```

三个设计决策：

1. **`is_free and not is_busy` 优先**：先判「明确空闲」，再判忙碌。原版的并列 `if` 在这里被修掉——现在两个关键词同时出现时结果确定（走忙碌分支）。
2. **数值必须落在 5–10 s**：板子给的等待时间就是 5–10 s，OCR 认成 `3` 或 `18` 说明某位数字认错，与其上报错值不如回退默认 `8 s`（取区间中位数附近，调度影响最小）。
3. **`秒` 字优先于裸数字**：先用 `(\d+)\s*秒` 精确匹配，匹配不到才退回 `(\d+)`——板面若出现「化验区 3」这类编号，粗匹配会误抓。

### 5. 发布与统计（`:74-140`）

| 话题 | 类型 | 内容 |
| --- | --- | --- |
| `/board2_result` | `Int32MultiArray` | `[is_busy, wait_s]`，`is_busy` 1/0 |
| `/board2_text` | `String` | Tesseract 原始识别串（去空白后） |

- 10 Hz（`rospy.Rate(10)`），`STATS` 记 `total/success/fail`
- 失败告警做了抽样：`if STATS["fail"] % 30 == 1`（`:118`）——10 Hz 下全量打日志会把 rosout 刷爆
- 按 `s` 存两路截图（原图 + 二值图，带时间戳，`:130-134`），按 `Esc` 退出；退出时打印 `success/total` 成功率（`:140`）
- `~headless=True` 可关掉全部 `imshow`，供车上无显示器运行

## 统计口径的坑

`STATS["success"] += 1` 的条件是 `if text:`（`:109-111`）——**只要 Tesseract 吐出了任意字符就算成功**，哪怕解析出的忙/闲是错的。所以 `STATS` 打印的「成功率」是「有输出率」，不是「判定正确率」。

投简历若引用这个数，必须换成人工标注集上的正确率；把「有输出率」说成「识别成功率」面试一追问就穿。这条已写进 `RESUME.md` 的「数字来源」表。

## 为什么离线通过、现场失败

现场结论：**离线测试能过，正式运行时识别失败，不稳定**。这个项目没有把它修到可用（时间预算被二维码与跑位吃满），但现象背后的原因是清楚的四条，任何一条单独成立都足以让离线结果不可迁移。

### 1. 统计口径把「有输出」当成了「判对」（`OCR_CAM.py:109-111`）

```python
if text:
    STATS["success"] += 1
```

Tesseract 只要吐出任意字符就记一次成功。离线测试时人眼看着「它认出了东西」，`success/total` 也好看；但**判对**要求同时满足「忙/闲关键词命中」与「秒数落在 5–10」，而后者失败时静默回退 `8`（`:52-71`）——**错答案长得和正确答案一模一样**，没有失败信号。这是最要命的一条：离线阶段没有任何指标在报警。

### 2. ROI 写死，默认「车停在同一位置」（`:17-19`）

`ROI_REGION = (100, 150, 600, 424)` 是赛前在一个确定停车位描出来的。离线复测时车几乎不动，ROI 必然对准；现场每次靠 move_base 停在容差内（`xy_goal_tolerance` 量级），横向几十厘米偏差 + 车头角度偏差，就会让板子在画面里平移出框、或字高变化导致 `blockSize=11` 的邻域尺度失配。**固定 ROI 的前提是停车精度，而这个前提没有在赛前被量化验证过。**

### 3. 自适应阈值对小字号太敏感（`:27-40`）

`ADAPTIVE_THRESH_GAUSSIAN_C, blockSize=11, C=2` 在均匀光照、白底黑字的样张上很好；现场是射灯 + 金属牌面半幅反光，`C=2` 的偏移量会让反光区的笔画整体吃掉或整体变粗，`chi_sim` 在 20–30 px 字号下丢掉一横一竖就是另一个字（「忙」「空」只差局部笔画）。

### 4. `psm 6` 依赖排版，现场字体/行距与样张不同

`--psm 6` 假设「单块文本」，两行紧凑排版时按行切分；样张是打印体，现场牌子若有轻微倾斜或行距变化，切出来先是一个字块里面混两行，`chi_sim` 输出直接乱序。乱序后关键词命中率骤降，走回退路径（静默 `8 s`）。

## 如果重做一次，最小验证闭环

1. **换指标**：用 30–50 张现场手机拍摄的板面图做人工标注集，统计「忙/闲判对率」与「秒数绝对误差」，取代 `STATS` 的「有输出率」。
2. **先量化停车误差**：实测 `xy_goal_tolerance` 下的落位分布，再决定 ROI 是放大到覆盖整个落位区间（后用轮廓校正回正），还是接板面检测而不是固定框。
3. **给失败留信号**：把「未命中关键词 / 秒数越界」显式记成 `fail` 并发布 `confidence=0`，让上层能感知「这一帧不可信」，而不是让它伪装成 `8 s`。
4. **小步对齐再 OCR**：先用板框做透视回正（沿用二维码那套四点法），保证字形尺度一致，再进 Tesseract。

这四条写在这里的价值不在「当时该怎么改」，而在**这类问题的排查顺序**：先怀疑指标，再怀疑输入（ROI/光照），最后才怀疑算法。
